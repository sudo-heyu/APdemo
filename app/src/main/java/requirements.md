# AP 质量评估系统 - 安卓展示端需求文档

## 1. 项目概述
本项目通过 **数据采集（测试机/本端）**、**后端（算法处理）** 与 **安卓展示端（结果呈现）** 的协作，实现对周边 Access Point (AP) 的智能化质量评估与打分。

## 2. 系统核心流程
系统以 **150秒 (2.5分钟)** 为一个完整的大周期进行循环运行：
1. **主动扫描阶段**：大周期开始时进行 **4次** 连续硬件 Wi-Fi 扫描（间隔 2 秒）。
2. **数据上传与初始同步**：汇总结果上传至服务器获取初始评分。
3. **动态监控阶段（轮询）**：剩余时间内每 **10秒** 纯软件查询一次最新分数，不触发硬件扫描。
4. **周期复位**：150秒结束后清除旧数据，开启新一轮主动扫描。

## 3. 核心功能模块
- **多轮 WiFi 扫描**：累积多轮数据提高信号覆盖准确性。
- **动态评分获取**：支持 10 秒高频轮询，体现后端算法分数的实时动态变化。
- **服务器配置管理**：
    * **初次引导**：无配置时自动弹窗。
    * **手动修改**：点击顶部菜单栏“设置”图标（Manage 图标）修改并立即生效。
- **用户支持与答疑**（新）：
    * **交互入口**：点击顶部菜单栏“问号”图标（Help 图标）。
    * **内容涵盖**：Android 硬件扫描频率限制说明、无数据排障指南（权限/Wi-Fi 开关）、服务器连接自检说明。
- **UI 可视化展示**：
    * 列表显示：SSID、信号强度图标、RSSI 值（dBm）。
    * 评分呈现：以浅蓝色（pale_blue）显示后端分数。
    * 理由查看：点击列表右侧展开图标查看 LLM 详细理由。

## 4. UI 排序与交互规则
- **排序权重**：有评分的 AP 优先置顶，同类按 RSSI 降序排列。
- **点击交互**：禁用整行点击，采用独立按钮展开/收起评分原因。

## 5. 技术架构
- **通信与处理**：OkHttp + Gson + Handler 定时器。
- **权限管理**：动态请求 ACCESS_FINE_LOCATION 等必要权限。
- **持久化**：使用 SharedPreferences 存储服务器地址信息。
