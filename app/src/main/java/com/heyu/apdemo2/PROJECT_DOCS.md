# APdemo2 项目文档

## 1. 项目概述
APdemo2 是一个 Android 应用程序，旨在扫描周围的 WiFi 热点（Access Points），并将扫描结果发送到后端服务器进行评估。应用会展示每个热点的评分和推荐理由，帮助用户选择最佳的 WiFi 连接。

## 2. 核心功能

### 2.1 WiFi 扫描与数据收集
- **扫描机制**: 应用通过 Android 的 `WifiManager` 进行 WiFi 扫描。
- **扫描周期**:
    - **采集阶段**: 进行一次扫描，完成后立即向服务器请求评分。
    - **监控阶段**: 采集完成后，进入 150 秒的等待期。
    - **循环**: 整个过程每 150 秒重复一次。

### 2.2 服务器通信与评分
- **配置**: 用户可以在应用内配置服务器的 IP 地址和端口号。
- **批量上传**: 在扫描完成后，应用会将收集到的 SSID 列表批量上传至服务器。
    - **接口**: `POST http://<IP>:<PORT>/api/upload_scan`
    - **请求体**: 包含 SSIDs 列表、数量和设备型号。
- **实时监控**: 在 150 秒的等待期间，应用每 10 秒向服务器轮询一次，获取最新的评分和理由。

### 2.3 用户界面 (UI)
- **列表展示**: 使用 `RecyclerView` 展示扫描到的 WiFi 热点。
- **信息内容**:
    - SSID (网络名称)
    - 信号强度 (RSSI)
    - 评分 (0-100)
    - 推荐/不推荐理由 (支持展开/折叠)
- **状态提示**: 顶部状态栏实时显示当前扫描或监控的状态。
- **交互**:
    - 下拉刷新 (通过周期性扫描自动触发)
    - 点击列表项可查看更多详情 (理由)
    - 菜单栏提供服务器配置和帮助说明。

## 3. 技术架构

### 3.1 模块划分
项目采用清晰的包结构设计：
- **`com.heyu.apdemo2`**: 根包
    - **`model`**: 数据模型
        - `AccessPoint.kt`: 定义 WiFi 热点属性（SSID, BSSID, RSSI, Score, Reason 等）。
        - `ScanResponse.kt`: 定义服务器响应的数据结构。
    - **`adapter`**: UI 适配器
        - `AccessPointAdapter.kt`: 处理 WiFi 列表的展示逻辑。
    - **`network`**: 网络层
        - `ApiService.kt`: 封装 OkHttp 请求，处理数据的上传和获取。
    - **`scanner`**: 扫描工具
        - `WifiScanner.kt`: 封装 Android WiFi 扫描 API。
    - **`MainActivity.kt`**: 主活动，负责协调 UI、扫描任务和网络请求的生命周期。

### 3.2 关键技术栈
- **语言**: Kotlin
- **网络**: OkHttp, Gson (JSON 解析)
- **UI**: XML Layouts, RecyclerView, Material Design
- **权限**:
    - `ACCESS_FINE_LOCATION`: 获取精确位置（扫描 WiFi 必需）
    - `ACCESS_WIFI_STATE` & `CHANGE_WIFI_STATE`: WiFi 状态管理
    - `INTERNET`: 网络通信

## 4. 使用说明
1.  **启动应用**: 首次启动需授予位置权限。
2.  **配置服务器**: 点击右上角设置图标，输入服务器 IP 和端口。
3.  **自动运行**: 配置完成后，应用会自动开始扫描循环。
    - 阶段 1: 连续扫描 4 次。
    - 阶段 2: 上传数据并显示初始评分。
    - 阶段 3: 每 10 秒刷新一次评分，持续 150 秒。
    - 阶段 4: 重新回到阶段 1。

## 5. 常见问题
- **无数据**: 请确保 GPS 已开启且授予了位置权限。Android 10+ 对后台扫描有限制。
- **评分获取失败**: 检查服务器配置是否正确，以及网络连接是否正常。
